# Phase 8 — Invoices: Test Report & Evidence

This phase adds **invoice records** and **customer-accessible invoice views**. An
invoice is the financial document of a **shipped** order: it is minted *atomically
inside the same transaction that consumes stock when an order reaches `shipped`*
(decision **D-25**), so it can never exist for an order that did not ship and never
twice for one that did.

## 1. What was verified (and how)

| Requirement (from the Phase 8 brief) | Where it is proven |
|---|---|
| Invoice generated at a documented lifecycle point | `→ shipped` (D-25); `invoice-http.test.js › no invoice until ship, then it appears atomically` |
| Unique number, safe under concurrency | per-year counter upsert-RETURNING; `invoice-http.test.js › consecutive shipped orders get strictly increasing yearly numbers` |
| Stores order id, issue date, subtotal, tax, total, status | `invoices` table + migration 17 (`status`/`void_reason`/`voided_at`); `db-integration › financial totals: order/invoice invariants enforced by CHECKs` |
| Uses the order's persisted snapshot, not client values | `invoice.service.generateForOrder` copies `order.subtotal/tax_total/grand_total`; `invoice-http.test.js › invoice totals and lines are immune to later catalog price edits` |
| Idempotent generation (no duplicates on retry) | `UNIQUE(order_id)` + `ON CONFLICT DO NOTHING` replay; `invoice-http.test.js › a second invoice for the same order is rejected by the UNIQUE constraint` |
| Customers access only their own invoices | ownership-scoped reads; `invoice-http.test.js › customers see only their own invoices; staff see all` |
| Admins + authorized staff can view | same test (staff see all); `GET /api/invoices` |
| Customers cannot alter totals/ownership | no client write path; strict Zod `voidInvoiceSchema` rejects injected money (`invoice-unit.test.js`); `customer cannot void` (403) |
| Cancelled orders & voided invoices handled | cancelled (pre-ship) order → `invoice-http.test.js › a cancelled order has no invoice`; void preserves the row → `admin voids an invoice (row preserved) and a re-void is refused` |
| Historical detail survives catalog changes | snapshot copy; `invoice totals and lines are immune to later catalog price edits` |
| Decimal-safe + totals validated | integer-cent money (D-09) + DB CHECK `grand = subtotal + tax`; `invoice-http.test.js › S+T=G` |
| Endpoints `GET /api/invoices`, `/api/invoices/:id`, `/api/orders/:id/invoice` | implemented + covered above |
| Professional printable page | `InvoicePage.jsx` (distributor, number, date, customer, order no., lines, totals, status) — see screenshots |
| Print CSS, no PDF dependency | `@media print` stylesheet + Print / Save-as-PDF button; **no PDF library added** |
| Labelled a demonstration document | `INVOICE_DEMO_NOTICE` banner on every view + in the API payload — see screenshots |
| Migration reversibility | migration 17 `down` restores the strict monthly CHECK; `db-integration › Migration reversibility` (test truncates `invoice_counters` first) |

## 3. How to reproduce the screenshots

The screenshots in [`../screenshots/`](../screenshots/) show real data generated by the
live happy-path smoke (it places a cart order and advances it to `shipped`, which mints
the invoice through the actual code path).

Prerequisites (Windows PowerShell — use `;`, never `&&`):

```powershell
# 1. Database (PostgreSQL 16 on host :5433)
docker compose up -d db

# 2. Apply migrations (incl. 17) and seed dev users/products
cd backend ; npm run db:migrate ; npm run db:seed

# 3. Start the API (http://localhost:4000)
npm start

# 4. In a SECOND terminal, mint a real shipped order + issued invoice for the demo
node scripts/smoke/phase8-invoice-smoke.js

# 5. In a THIRD terminal, start the SPA (http://localhost:5173, proxies /api -> :4000)
cd ..\frontend ; npm run dev
```

Dev logins (seed): `customer@b2boms.test` / `admin@b2boms.test` / `agent@b2boms.test`,
all password `Passw0rd!`.

> Note: the backend `CORS_ORIGINS` default allows `http://localhost:5173`. If the Vite
> dev server falls back to another port (e.g. 5174 because 5173 is taken), either free
> 5173 or add that origin to `backend/.env` `CORS_ORIGINS` and restart the API.

### Capture steps

1. Sign in as **`customer@b2boms.test`** → **Invoices** → `15-invoice-list-customer.png`
   (own invoices, Issued/Voided badges, server totals, **no** Customer column / filter).
2. Open an **Issued** invoice → `16-invoice-printable-issued.png` (demonstration banner,
   distributor block, invoice number/date/order no., bill-to, line items, Subtotal/Tax/Total).
3. Open a **Voided** invoice → `17-invoice-printable-voided.png` (red **VOID** stamp + reason).
4. Sign in as **`admin@b2boms.test`** → **Invoices** → `18-invoice-list-staff.png`
   (adds the **Customer** column and the **Status** filter).
5. Open an **Issued** invoice as staff → `19-invoice-staff-void-button.png`
   (the staff-only **Void this invoice** control below the document).

To exercise the browser print stylesheet, open an invoice and press **Print / Save as
PDF** (or Ctrl/Cmd-P): the toolbar and navigation chrome are hidden via `@media print`
and only the document prints — no PDF dependency is involved.
