# Risk Register — B2B Order Management Platform

**Document version:** 1.0 (Phase 1 — Planning & Design)
Scoring: **Probability** and **Impact** on a 1–5 scale (5 = highest); **Score = P × I**, reviewed each phase. Risks with score ≥ 12 must have a mitigation *designed before* the relevant phase starts and a verification test listed in `implementation-plan.md` §2. **No risk below is "closed" — all are open until their mitigation is built and tested in Phases 2–5.**

| ID | Risk category | Description & scenario | P | I | Score | Mitigation (design) | Verification | Residual owner |
|---|---|---|---|---|---|---|---|---|
| **R-01** | **Overselling / stock integrity** | Concurrent orders sell stock that doesn't exist, or reservations are lost/duplicated. Scenario: two flash-sale customers order the last unit simultaneously; spreadsheet-era distributors lose credibility if the platform confirms unfillable orders. | 4 | 5 | 20 | Transaction-scoped `SELECT … FOR UPDATE` row locks ordered by product ID (D-06); DB `CHECK (available_quantity >= 0)` as last line of defense; `inventory_movements` ledger making stock reconcilable; atomic rollback on any line failure (FR-ORD-02/03). | AC-ORD-02 (rollback), **AC-ORD-05** (20 concurrent × stock 5, 10 runs), ledger-reconciliation test | Dev — closes when load test evidence recorded |
| **R-02** | **Unauthorized access** | Customer A reads/cancels Customer B's orders; agent escalates to admin actions; disabled ex-employee token keeps working. Financial and trust damage; near-legal in B2B (competitors' order volumes). | 3 | 5 | 15 | Backend RBAC on every route (D-05); ownership filters applied in services; cross-owner reads → 404 (no existence leak); per-request user re-check so `is_active=false` kills old tokens immediately (D-04); short 2 h JWT TTL. | AC-AUTH-06/07, AC-CART-05, AC-LIF-05, AC-AUD-03; NFR-04 | Dev |
| **R-03** | **Incorrect totals / money math** | Float rounding, mixed rounding policies, or client-supplied amounts corrupt order/invoice totals. Scenario: `0.1+0.2` style drift makes `subtotal + tax ≠ grand_total`; disputes with customers; accounting rejects invoices. | 3 | 4 | 12 | Integer-cent arithmetic confined to `utils/money.js` (D-09); `NUMERIC(14,2)` in DB; half-up per-line rounding rule documented; server recomputes everything, client values ignored (FR-ORD-01/AC-ORD-03); invariant `G = S + T` enforced in code and tests. | `money.test.js` fixtures/properties (AC-CART-02), AC-ORD-03, AC-INV-01 | Dev |
| **R-04** | **Duplicate orders** | Double-click, retry after timeout, or parallel client bugs create N orders from one intent, decrementing stock N times. | 4 | 4 | 16 | Mandatory `Idempotency-Key` with `UNIQUE(user_id, key)` claim-row (D-08); stored response replay (`200 idempotent`); concurrent in-progress duplicate → `409 DUPLICATE_REQUEST`; key required *before* any stock work. | AC-ORD-04/07 incl. staggered parallel send; SC-03 (100/100) | Dev |
| **R-05** | **Data loss** | Volume wipe, bad migration down-run, or failed deploy destroys orders/invoices. B2B records are financial; loss is unacceptable. | 2 | 5 | 10 | Named Docker volume (not bind/anonymous); migration discipline: reversible up/down scripts tested with `up → down --to 0 → up` in CI (database-design §4.6); documented `pg_dump`/restore procedure *and drill* before pilot (Q-04); FK/CHECK constraints keep data valid; audit log + snapshots make reconstruction possible (NFR-13). | NFR-DEPLOY-01 persistence step; Q-04 drill record signed by operator | Dev/Ops |
| **R-06** | **Secret exposure** | JWT secret or DB password committed to Git, printed in logs, or returned in responses. A leaked signing secret = full account takeover (multiplies R-02). | 3 | 5 | 15 | Env-vars-only config validated at boot (fail-fast if missing); `.env` in `.gitignore`, only `.env.example` committed (NFR-03); request logger records metadata only, bodies excluded on auth routes; AuditService whitelists detail keys (D-11); bcrypt hashes never serialized (repository `toPublic()` projection). | NFR-SEC-02 secret scan; AC-AUD-02 log grep; AC-AUTH-03; code-review checklist | Dev |
| **R-07** | **Deployment configuration** | `docker compose up` works on the dev machine but fails elsewhere: stale images, missing env, wrong port, migrations skipped, WSL2/Docker drift. "It works on my machine" stalls the pilot. | 3 | 3 | 9 | Pinned image tags (`postgres:16-alpine`) and lockfiles committed; migrate-on-boot with version logging; healthcheck gates API readiness; `.env.example` documents every variable; fresh-environment checklist executed as NFR-DEPLOY-01 (machine with Docker only); prior environment pitfall (Docker daemon/WSL2) documented in README. | NFR-DEPLOY-01 pass on a clean profile/machine, evidence in phase report | Dev |
| **R-08** | Performance / lock contention | Row locks serialize ordering; catalog reads degrade under load. Unlikely at A-07 scale but blocks pilot growth. | 2 | 3 | 6 | Lock only inventory rows, held only for the transaction's duration; locks taken in deterministic product-ID order (deadlock avoidance); indexes per database-design §4.4/4.5. | NFR-PERF-01 load test with measured p95 reported (or honest "not measured") | Dev |
| **R-09** | State-machine bugs | A missed transition guard lets a cancelled order be fulfilled (stock already released) or a fulfilled order cancelled (invoice orphaned). | 2 | 4 | 8 | Single `ORDER_TRANSITIONS` map in OrderService (data-driven, not if-chains); terminal states `fulfilled/cancelled`; illegal attempts → `409`; invoice `UNIQUE(order_id)` prevents re-invoicing. | AC-LIF-01…06 full matrix test | Dev |
| **R-10** | Scope creep / design drift | Out-of-scope asks (payments, PDFs, price lists) arrive mid-build, diluting the Must-have quality bar. | 3 | 3 | 9 | Explicit out-of-scope list (requirements §3.2) + D-14 scope-freeze entry; new asks go to the open-decision/backlog table, only in via a logged decision + AC update. | Phase-exit reviews check docs vs. code (release definition item 5) | Product owner |
| **R-11** | Test-vs-reproduction gap | Integration tests pass against a test DB but production-like concurrency behavior differs (pool exhaustion, timing). | 2 | 3 | 6 | Same PostgreSQL 16 version in test/compose (D-03); dedicated `DATABASE_URL_TEST`; load scripts run through the real Express app, not mocked layers. | AC-ORD-05 executed against compose stack in Phase 3 | Dev |

## Review protocol

1. Re-score all rows at each phase exit; add discovered risks immediately (release definition item 4 in `acceptance-criteria.md`).
2. A risk closes only with: mitigation implemented → listed verification executed → evidence (test name/run output) linked in the phase report.
3. Highest-priority build order implication: R-01/R-04 controls are part of task B-05 and gate Phase 4 start (implementation plan §3.3).
